Understanding Retrieval-Augmented Generation (RAG)

RAG (Retrieval-Augmented Generation) is a technique that combines retrieval of external knowledge with generative language models to produce more accurate, up-to-date, and verifiable responses.

How RAG works:
1. Indexing: A knowledge base of documents is split into chunks, embedded using a text embedding model, and stored in a vector database.
2. Retrieval: Given a user query, the system computes the query embedding and retrieves the most similar document chunks from the vector store (using cosine similarity or nearest neighbors).
3. Generation: The retrieved chunks are appended to the user's question as context, and a generative LLM produces a final answer grounded in those chunks.

Why use RAG instead of plain prompting?
- Factual accuracy: The model draws from verified sources rather than memorized training data.
- Up-to-date knowledge: The knowledge base can be updated without retraining the model.
- Attribution: Responses can cite the source documents they pulled from.
- Domain specificity: You can tailor the system to a private corpus (e.g., company docs, research papers).

Popular RAG frameworks and tools include LangChain, LlamaIndex, Haystack, and semantic-kernel. Simple RAG pipelines can also be built from scratch using sentence-transformers and FAISS.

Common RAG improvements:
- Re-ranking: A cross-encoder re-ranks retrieved chunks for better relevance.
- Query expansion: The system generates variant queries to improve recall.
- Metadata filtering: Documents are filtered by tags (date, author, category) before retrieval.
- Hierarchical retrieval: Summarize chunks, then drill into the most relevant ones.
